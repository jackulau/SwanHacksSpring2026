# HackStack Architecture Audit

> Generated by the architect agent during the parallel feature execution pass.
> Source of truth for the architectural decisions surfaced in this round.

## Executive summary

- **The frontend is a thin client doing the work of a backend.** AI pipeline, OpenAI key, Deepgram key, all lecture-processing orchestration, and Canvas token storage live in browser code (`frontend/src/lib/ai-pipeline.ts:17`, `frontend/src/hooks/useDeepgramSTT.ts:39`, `frontend/src/lib/canvas.ts:50-67`). For a hackathon this is fine; for anything beyond demo day it is the single largest architectural problem.
- **PocketBase access rules are inconsistent.** `courses` and `lectures` are user-scoped (`backend/pb_migrations/1777500000_hackstack_collections.js:9-13, 31-36`), but `transcripts`, `notes`, `flashcards`, `quizzes`, `quiz_attempts`, `study_sessions` ship with all rules set to empty string (`""`). In PocketBase that means **admin-only access for queries with no auth header**, but with an authenticated user it allows full access — this is a security hole when client-direct.
- **The provider tree as currently shipped is correct and the audio player work fits cleanly.** Reading aids are well-architected. The biggest near-term risk is not a refactor — it's the AI pipeline running on the main UI thread of `routes/capture.tsx` with no recovery if the tab is closed mid-generation.

## Verdict

**Ready for hackathon demo. Needs ~5 changes for a believable v1.** No blocker to shipping the remaining 6 features in `tasks/remaining-features-spec.md`. Two of the five required changes are server-side (AI pipeline relocation, PB rule fixes) and would only be tackled post-demo.

## 1. Provider tree integrity

Current order in `frontend/src/main.tsx:17-23`:

```
AuthProvider > PreferencesProvider > AudioPlayerProvider > RouterProvider
```

Correct. `PreferencesProvider` calls `useAuth()` (`preferences.tsx:123`), so `AuthProvider` must wrap it. `AudioPlayerProvider` doesn't consume `useAuth` or `usePreferences` today — its position is flexible. `RouterProvider` must be innermost.

A future `StudySessionProvider` should sit at the same level as `AudioPlayerProvider` and inside `AuthProvider` — `useStudySession` reads `user.id`. Order:

```
Auth > Preferences > AudioPlayer > StudySession > Router
```

Cautions:
1. `applyToDOM` mutates `document.documentElement` synchronously inside an effect. Document the convention: only `PreferencesProvider` writes `documentElement.style` / dataset.
2. PB sync errors are silently swallowed (`preferences.tsx:138`). Add a toast-or-log policy at the provider boundary.

## 2. State management

Today: React context for cross-cutting concerns; per-route `useState` + direct `pb.collection(...).getFullList()` inside `useEffect` for server data. `routes/lectures.$lectureId.tsx:42-90` has six sequential PB reads on mount — no caching, no dedup.

Where it scales fine: dashboards, lecture lists.

Where it breaks down:
- 5 sequential PB requests on lecture detail mount. Cold-cache: ~400ms wasted, sequential.
- Optimistic updates have no helper.
- `useSM2.ts` writes to `flashcards` directly without invalidating any reads, so list views stale until remount.

**Recommendation:** TanStack Query is already in `package.json:17` but unused. Migrating the 6 main read paths is ~3h work and adds dedup/retries/stale-while-revalidate/mutation invalidation for free. v1.1 cleanup, not hackathon-blocking.

---

## 3. PocketBase realtime

Where it pays off:
- `lectures` status during AI processing (`ai-pipeline.ts:64-68`). Subscription on `lectures` filtered by user gives the Dashboard a free progress badge.
- `study_sessions` for the streak feature — completing a Pomodoro updates the streak without reload.

Where it costs too much:
- `flashcards` table — every rate triggers an update during SM-2 review. Subscribing fires one event per rate across all open tabs.
- `transcripts` and `notes` — once written, they don't change.

**Ground rule:** Subscribe to entities whose `status` field changes (lectures), not to entities that are append-mostly (flashcards, quiz_attempts).

PB realtime uses SSE; pair every subscription with a `document.visibilitychange` listener to disconnect when hidden.

## 4. AI pipeline

Invoked only from `routes/capture.tsx:126`, inside a component-level `useEffect`.

Concerns, priority order:

1. **Tab-close = data loss.** No on-load reconciliation step that finds stuck lectures and resumes them.
2. **API key is in the browser bundle** (`ai-pipeline.ts:17` reads `VITE_OPENAI_API_KEY`). Same for Deepgram. Anyone with devtools can extract.
3. **No queue.** `runPipeline` runs four OpenAI calls **sequentially**, each with `withRetry` × 3 attempts. Worst case: 12 sequential network calls × ~5s. Notes/flashcards/quiz are independent — should run in parallel via `Promise.allSettled`.
4. **`max_tokens: 4096`** silently truncates long lectures. No chunking strategy.
5. **Errors stringified loosely.** `ai-pipeline.ts:139` does `${e}` → `[object Object]`.

Cheap mitigations:
- Stuck-lecture sweeper on app load (~10 lines).
- `Promise.allSettled` parallelization — 4× wall-clock improvement.
- Move OpenAI call to PocketBase JS hook (`backend/pb_hooks/`) — one extra file.

## 5. File storage

Audio stored as PB attachments on `lectures`. Capture uses `audio/webm;codecs=opus` at 64kbps.

- 64kbps × 60min ≈ 28 MB/h.
- 1000 users × 50 lectures × 30MB ≈ 1.5TB.

Real concern for v1: 5GB Fly volume holds ~166 large uploads. Plan for S3-compatible storage (Backblaze B2, R2) before there's enough load. PB supports S3 backends via env config — zero code change. Put a CDN in front (Cloudflare free tier).

## 6. Auth

PB SDK defaults to `localStorage` under `pb_auth`.

- **No session refresh.** PB tokens default to ~7 days. Add `authRefresh()` on app focus.
- **CSRF risk: low** (bearer tokens, not cookies). XSS-vulnerable instead — keep escaping content.
- **Login route hardening:** `routes/login.tsx` does no rate-limiting client-side; PB handles it server-side (verify it's enabled at deploy).
- **Password minLength is 8** — OK for hackathon.
- **No "remember me" toggle.** Tokens always persist.

---

## 7. Canvas integration

`frontend/src/lib/canvas.ts` + Vite middleware proxy in `vite.config.ts:11-39`.

Concerns:

- **The proxy only exists in dev mode.** Production (`vite build`) emits a static bundle — no runtime proxy. **Canvas integration only works during `npm run dev`** unless a backend proxy is added.
- **Token in localStorage** has same XSS profile as auth token. Worse: it grants access to *all* Canvas data (courses, assignments, grades).
- **No token refresh story.** When tokens expire → 401 with no UX to re-prompt.
- **No CORS-bypass strategy in production.** Need backend proxy: Express/Workers function or PB JS route handler.

## 8. Reading aids cross-cutting

`ReadingRuler.tsx` and `FocusMode.tsx` mount once globally in `AppShell.tsx:140-141`.

Ruler perf: subscribes to `mousemove` on `window` — fires up to 60 events/sec. Each calls `setY`. React 19 batches per event tick, but no rAF throttle — adding one would drop renders by ~50% during fast cursor moves.

Focus Mode perf: already coalesces with rAF (`FocusMode.tsx:179`) — good. `getSentenceRects` ~1ms per frame on 200-word paragraph. Fine.

Bug to flag: paragraph mode swaps a CSS class that triggers transition animations on every sibling in the focus zone. On a 200-paragraph transcript that's 200 simultaneous opacity transitions. `prefers-reduced-motion` early-out is already done — test on low-end devices.

## 10. Test posture

No test infrastructure today. Highest-leverage hackathon investment, in order:

1. **One Playwright happy-path E2E** — login → record → wait `ready` → flashcards. ~2h.
2. **Vitest for `lib/sm2.ts`, `ai-pipeline.ts` parseJSON helper, `useStudyStreak` date-grouping** — pure-function code with subtle bugs. ~1h.
3. **Skip Storybook** for hackathon.

Don't aim for 80% coverage now — aim for "demo doesn't break."

---

## 11. Observability

For demo day, pragmatic minimum:

- Sentry frontend SDK (`@sentry/react`, free tier) — global error handler. ~15min install.
- `console.error` filter writing to `localStorage` as fallback.
- Structured logging in `ai-pipeline.ts` — replace generic `errors` array with `console.error('pipeline.notes_failed', e)`.

Don't add Posthog/analytics — eats 2h, adds nothing to pitch.

## 12. Deployment story

Smallest viable production setup:

| Component | Where | Cost |
|---|---|---|
| Frontend (Vite static) | Vercel / Cloudflare Pages | $0 |
| PocketBase | Fly.io single VM with persistent volume (1GB) | ~$2/mo |
| Canvas proxy | Cloudflare Worker | $0 |
| OpenAI/Deepgram | direct API (move keys server-side ASAP) | per-use |
| File storage | PB-local on Fly volume | included |
| DNS | Cloudflare | $0 |

**Blocker for production today:** the Canvas proxy (Vite-only). Frontend is otherwise deploy-ready.
